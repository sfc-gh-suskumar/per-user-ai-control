The Problem

As organizations adopt Snowflake AI services — AI Functions, Cortex Agents, Snowflake Intelligence (CoWork), and Cortex Code (CoCo) — AI credit consumption grows rapidly and unpredictably across hundreds or thousands of users.

⚠
No Per-User Visibility
Traditional budgets track aggregate spend. There's no way to see which individual user is burning credits fastest.
💸
Runaway Costs
A single user running AI_COMPLETE over a large dataset can consume hundreds of credits in minutes, with no automatic stop.
🔒
No Tiered Control
Different teams and roles need different spending limits. One-size-fits-all doesn't work for varied AI usage patterns.
🔔
Reactive, Not Proactive
Admins discover cost overruns after the fact. By the time a bill arrives, the damage is done.
The core question: How do you enable broad AI adoption across your organization while maintaining per-user spending guardrails, real-time enforcement, and operational visibility?
Page 02

The Solution: Per-User Quotas

Snowflake's Per-User Quotas (GA feature, SNOWFLAKE.CORE.QUOTA) enforce per-user spending limits at the platform level. This framework builds on that with a tiered model, automated tagging, and an admin app.

Tiered Quota Model

Users are assigned to tiers via a tag. Each tier has its own daily and monthly credit limits, enforced independently.

TIER 1 StandardTIER 2 Power UserTIER 3 Heavy User
Daily Limit1 credit2 credits3 credits
Monthly Limit10 credits20 credits30 credits
Notifications50%, 80%, 100% actual — both daily and monthly cycles
Block EnforcementAutomatic — user blocked when daily OR monthly limit exceeded
Covered ServicesAI Functions, Cortex Agents, Snowflake Intelligence, Cortex Code
Limits are customizable. The values above are defaults. Adjust daily/monthly limits, number of tiers, and notification thresholds to match your organization's needs.

Key Capabilities

  • Daily and monthly per-user credit limits, enforced independently
  • Automatic blocking when limits are exceeded (within minutes)
  • Email notifications at configurable thresholds (user + admin)
  • Tag-based user routing — move users between tiers instantly
  • Automatic tagging of new users to a default tier
  • Exempt user list for service accounts or executives
  • Audit trail for every admin action with ServiceNow ticket tracking
  • Blocks auto-release at cycle reset (daily at UTC midnight, monthly on the 1st)

Architecture

The framework has six layers: Admin App, Cache, Scheduled Tasks, Per-User Quotas, Tag System, and AI Services. Data flows top-down for reads and bottom-up for credit metering.

How It Works

1
Users are tagged to a tier
The AI_COST_TIER tag on each user object determines which quota applies. New users are auto-tagged to TIER_1 by a daily scheduled task.
2
Users consume AI services
Every AI function call, Cortex Agent interaction, CoWork session, and CoCo usage is metered per-user and attributed to their quota.
3
Quotas evaluate and enforce
Within minutes of spend, the enforcement pipeline compares usage to limits. At 50%/80%/100%, email notifications fire. At 100%, the user is blocked.
4
Admins manage via the app
The Streamlit app provides a single pane of glass for quota management, tier changes, block status, and audit logging.
Page 04

Admin App

A Streamlit-in-Snowflake application deployed under the QUOTA_ADMIN role. Every write operation requires a ServiceNow ticket for audit compliance.

Quota Management
View/edit daily & monthly limits, manage notification thresholds, toggle block enforcement per quota.
Tag Management
View tier assignments across all users. Move users between tiers (change tag value).
Block Status
See currently blocked users per quota. Perform tier upgrades to unblock.
Tier Lookup
Real-time tag lookup via SYSTEM$GET_TAG() — bypasses the 2-hour ACCOUNT_USAGE lag. Single and bulk lookup.
Exempt Users
Manage the exemption list. Exempt users are excluded from automatic tagging and quota enforcement.
Untagged Users
Find users who don't have a tier tag yet. Bulk-assign them to TIER_1 or run the auto-tag procedure.
Execution Log
View automated procedure run history (TAG_NEW_USERS). See skipped users with detailed error reasons.
Audit Log
All manual write operations with the operator's username, timestamp (CST), and ServiceNow ticket reference.
Audit compliance: Every quota change, tier move, threshold edit, and exemption update is logged with who did it, when, and the ServiceNow ticket number.

Deployment

Three files, three steps. The entire framework deploys in under 15 minutes.

1
Run 01-setup.sql
Creates QUOTA_ADMIN and AI_USERS roles, grants, database, schema, tables, procedures, and scheduled tasks. Runs as SECURITYADMIN → SYSADMIN → ACCOUNTADMIN → QUOTA_ADMIN (sequential role switches within the script).
2
Run 02-create-quota.sql
Creates the 3 quota objects (TIER1, TIER2, TIER3) with limits, notification thresholds, block enforcement, and admin email. Runs as QUOTA_ADMIN.
3
Deploy Streamlit App
Upload streamlit_app_sidebar.py and font files to Streamlit-in-Snowflake via Snowsight. Deploy under the QUOTA_ADMIN role. See deployment-instructions.md for detailed steps.

Tier Limits

Adjust daily and monthly credit limits in 02-create-quota.sql:

-- Example: Set TIER 2 to 5 credits/day, 50 credits/month
CALL tier2_quota!SET_PER_USER_LIMIT(50);           -- monthly
CALL tier2_quota!SET_PER_USER_LIMIT(5, 'DAILY');   -- daily

Notification Thresholds

Add or remove notification thresholds at any percentage:

-- Add a 70% projected monthly warning
CALL tier1_quota!ADD_NOTIFICATION_THRESHOLD(70, 'PROJECTED', TRUE, 'MONTHLY');

-- Remove the 50% daily threshold
CALL tier1_quota!REMOVE_NOTIFICATION_THRESHOLD(50, 'ACTUAL', 'DAILY');

Adding More Tiers

Create additional quota objects following the same pattern in 02-create-quota.sql. Add the new tag value (TIER_4, etc.) and update the Streamlit app's QUOTAS list.

Covered AI Services

Control which services are metered per quota:

-- Add a specific Cortex Agent
CALL tier1_quota!ADD_SHARED_RESOURCE(
  'CORTEX AGENT',
  (SELECT SYSTEM$REFERENCE('CORTEX AGENT', 'my_agent'))
);

-- Add a specific warehouse
CALL tier1_quota!ADD_SHARED_RESOURCE(
  'WAREHOUSE',
  (SELECT SYSTEM$REFERENCE('WAREHOUSE', 'MY_WH'))
);
